## Что уже является общим языком игры

`AdventureTheme.kt` полностью задаёт роли палитры, два встроенных шрифта и пять
размеров срезанных форм. `AdventureChrome.kt` содержит рамочные кнопки/панели,
ромбические разделители, заголовки и декоративный индикатор переключателя.
Это реальные общие компоненты, а не смена только primary-color. Использование
MaterialTheme/Surface само по себе не является дефектом: критерий разрешает
Material3 как техническую основу, проверять нужно итоговую подачу.

| Область | Подтверждено исходниками | Оставшаяся неоднородность |
| --- | --- | --- |
| Главное меню | Иллюстрация костра, типографика, свои MenuEntry, рамочные заголовки и фон | Подтверждения выхода в `App.kt` используют стандартную композицию AlertDialog/TextButton |
| Создание/вход/лобби | Сцена костра, AdventurePanel приглашения/отряда, AdventureButton входа/старта, оформленная история | Три поля `NetworkScreen.kt` используют обычные OutlinedTextField без общего оформления полей; статусы/ссылка reconnect и выход остаются отдельными Material-композициями |
| Библиотека/редактор героя | Рамочные карточки, отдельный ряд действий, фон, секции редактора, собственное оформление текстовых полей и кнопок выбора, semantics выбора аватара | Popup выбора в `CharacterOption` — обычный DropdownMenu/DropdownMenuItem; удаление использует AlertDialog, хотя его кнопки уже свои |
| Разговорная сцена | Переиспользуемые окружения/фигуры, нижняя прозрачная типографика субтитров, свой слой сцены | Drawer, ввод, панели героя/проверки, журнал и их действия не переведены целиком на общие рамки; сохранились явно RoundedCornerShape(10/12/14) рядом со срезанной темой |
| Бой | Своя карта/сетка/аватары, полноэкранные постановки, цель/маршрут повозки; execute — AdventureButton | Выбор приёмов остаётся FilterChip, окончание хода — OutlinedButton; очередь, map frame и hint задают отдельные rounded-формы; журналы/справка — AlertDialog |
| Кубики | Собственная геометрия, свет/палитра, шрифты, раскрытие подтверждённого результата | Кнопки показа/продолжения — TextButton; следует согласовать их с общим действием без утяжеления центрального кадра |
| Настройки | Общая AdventurePanel, собственные переключатели, раздельные каналы и сохранение, preview размера субтитров | Три громкости и размер субтитров используют Slider со стандартным thumb/track; встроенное окно — AlertDialog, у кнопки «Готово» не задана общая форма |
| Пролог/финал | Только иллюстрация и общие субтитры, согласованный автоматический показ | Material-control в самом кадре нет; здесь не нужен новый декоративный UI |
| Локальная подготовка/учебный бой | Берут общие фон/героев/тему и боевую постановку | LocalAdventureSetup ещё использует прежние OutlinedButton/Button; нижний приоритет, чем основной сетевой путь |

Не считать каждый найденный вызов Material3 дефолтным визуальным стилем:
например, ScenarioPicker уже задаёт собственные формы/цвета, а большинство
TextButton/OutlinedButton наследуют срезанную форму и палитру. Слабое место —
отсутствие одной композиции для полей, выбора, вспомогательных окон и действий,
а не сам импорт библиотеки.

## Читаемость и поведение: доказанное и требующее проверки

- Численно рассчитаны sRGB-контрасты непрозрачных пар на `AdventurePanelColor`
  `#18262F`: основной текст `#F0E9DD` — 12.82:1, muted `#9BACB4` — 6.60:1,
  gold `#E8B975` — 8.57:1, green `#9CC8AB` — 8.30:1, error `#F2A79C` — 7.95:1.
  Это проверка только известных пар. Она не доказывает контраст текста на фото,
  полупрозрачных поверхностях, hover/disabled-состояниях и движущихся кадрах.
- Боевая карта/очередь/подписи используют фиксированные 8–12 sp; сводка героя
  содержит 10 sp. На телефоне это реальный кандидат для увеличения или иной
  иерархии. Сам факт малого sp не доказывает обрезку или нечитаемость конкретного
  устройства; нужны размеры/шрифтовый масштаб и пользовательский просмотр.
- ActionComposer содержит горизонтальную пару поля и кнопки, CheckPanel — пару
  длинных действий, выбор боевых приёмов идёт по два FilterChip в Row. Это места
  для проверки длинных русских названий/системного font scale; FlowRow/вертикальная
  адаптация предпочтительнее жёстких ширин, если переполнение подтвердится.
- Субтитры уже имеют диапазон 80–140%, тень, полный layout до раскрытия букв и
  защиту UTF-16. При 140% длинный сегмент до 180 символов на низком телефоне может
  занимать большую часть сцены; никакой проверки точного числа строк на таких
  сочетаниях здесь не выполнено. Не объявлять этот режим принятым по unit-тесту.
- `GamePreferences.motion` в UI называется **«Движение камеры»**. Он отключает
  трансформацию фонов, а часть общих кнопок/поз/escort учитывает его дополнительно.
  Это не полноценный общий reduce-motion: вращение кубика, перемещение бойцов,
  interaction-рывок, дыхание аватаров и пульсация карты остаются анимированными.
  Не обещать «все движения отключены» и не менять смысл настройки молча.

## Конкретные следующие срезы

1. **Точность пользовательской справки.** В `AdventureScreen.kt`, блок правил,
   остаётся фраза «Озвучка пока недоступна», противоречащая подключённым каналам
   и настройкам. Исправить на актуальное описание текста/голоса; новых API для
   этого не нужно. Пока это read-only finding, runtime во время сборки не менялся.
2. **Общие окна и поля основного пути.** Оформить reusable рамочное окно поверх
   безопасной Material dialog-основы, единое текстовое поле и вторичное действие;
   применить к лобби, настройкам и меню приключения. Сохранить focus/IME, semantics,
   скролл длинного содержания и доступность кнопок. Не добавлять подтверждений
   принятых игровых способов действий.
3. **Контекстные панели разговора/боя.** Выбор героя/действий, проверка и end-turn
   должны иметь одну рамочную иерархию. Для выбора приёма допустим Material-chip
   механизм, но нужна единая форма/обводка/selected/focus-подача. Объединить
   конфликтующие rounded/cut-frame решения после оценки направления стиля.
4. **Настройки и малая типографика.** Собственный Slider thumb/track при сохранении
   range/steps/accessibility, проверка длинных названий и текста на телефоне.
   Сначала измеримые ограничения и одна связная итерация, затем обратная связь
   пользователя на отдельной согласованной сборке.

`MediaGenerationSetting.kt` содержит старую карточку/выключатель и устаревшую
подсказку, но `rg` нашёл только определение, без вызовов. Не выдавать мёртвый
компонент за текущий экран демо и не тратить на него приоритет основной подачи.

Критерий 7 остаётся незавершённым: общий язык реализован в основном меню,
подготовке и героях, но оставшиеся оболочки/состояния и человеческая визуальная
оценка ещё нужны. Аудит не запускает новую сборку и не меняет checkpoint14.
