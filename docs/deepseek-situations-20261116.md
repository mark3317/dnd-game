# DeepSeek V4 Pro: ситуации и кеш · 16.11.2026

17/17 запросов завершены без транспортных ошибок, все ответы разобраны
серверным парсером. Медиана первого текста **3,042 с**, полного ответа
**4,327 с**. Диапазон полного ответа 3,545–10,686 с.
14/16 решений прошли механическую рубрику. Отдельная реакция на провал
сохраняет неуспех. Это не означает безупречности художественного текста.

## Метод

Восемь снимков demo-v1 по два одинаковых запроса подряд, затем GM28 — реакция
на подтверждённый провал. Полный серверный промпт и схема экспортированы через
MockEngine; заменена модель на deepseek-v4-pro-0813, reasoning оставлен по
умолчанию провайдера, как в предыдущем сравнении. Лимит ответа 1200 токенов.
Настоящий SSE, без TTS, без параллельной нагрузки, без повторов ошибок.
Рабочая игра и её модель не изменены.

Использован автоматический кеш DeepSeek, ранее подтверждённый счётчиками.
Недокументированные параметры кеша не добавлялись. Тела внутри пары идентичны,
SHA256 записан в локальном журнале; между ситуациями меняется состояние.
Нет принудительно отключённого кеша для контрольного сравнения.

GM08 — диагностический pendingCheck: в настоящей партии такой ввод не
отправляется модели. Движок не применяет ответ во время ожидающего броска.
GM10/GM11 проверяют подготовку проверки, а не вычисление моделью результата
кубика. GM28 содержит подтверждённый провал CHARISMA: die=1, modifier=-1,
total=0, difficulty=10; израсходована одна проверка, новых фактов нет.

GM28: первый текст 3,538 с, полный ответ 5,793 с, cache-read=0 из
12025 входных токенов. Это другой промпт для реакции на подтверждённый исход.

Положительный cache-read в 15/17 ответах. Все восемь повторов читают более
99% входных токенов из кеша. Шесть повторов быстрее первых запросов.
Медиана первых запросов пары 4,605 с, повторов 4,160 с: примерно на 9,7% меньше.
Первый текст: медианы 3,135 → 2,922 с.

Это наблюдаемая разница, не причинная оценка ускорения кешем: часть первых
запросов уже попала в кеш; ответы различаются по длине и содержанию.
Быстрый повтор GM02 вообще выбрал другое действие. Поэтому 9,7% нельзя
выдавать за гарантированный выигрыш при одинаковом качестве.

## Качество: оценка агентом

- GM02: первый ответ по существу; повтор выбирает BRIEFING с narration=null.
  Движок принимает действие, но рубрика требует ответа NPC без нового действия.
- GM04: обсуждение не стало действием. Первый ответ смешивает ремарку Агаты
  и цитату с speakerNpcId=ARCHIVIST; второй добавляет жест Рина из головы.
- GM08: оба сохраняют pendingCheck и ресурсы. engine_accepted=false ожидаемо:
  ввод блокируется движком во время броска. Число оставшихся проверок не
  сообщается: правила запрещают технические пояснения в narration. Это не
  подтверждение способности модели отвечать на справочные вопросы.
- GM10: оба создают DEXTERITY-проверку сложности 10 с отмычками. Во втором
  inputPresentation утверждает «открывает замок» вместо попытки. Сам движок
  дверь до броска не открывает.
- GM11: оба сохраняют INTELLIGENCE, сложность 10, LOCKPICKS и добавление
  CELLAR_DOOR_OPEN только при успехе. Домены LOCKS/DEVICES/CRAFT допустимы,
  планы приняты движком; подача описывает попытку.
- GM13: первый описывает передачу при plan=null — вещь не передана, команда
  не принята. Второй содержит корректный transfer-план, принятый движком.
  Предварительная речь в обоих случаях преждевременно утверждает передачу.
- GM14: оба запрещают передачу через разные локации; предметы не перемещаются.
  Но в первом превью утверждается передача, противоречащая итоговому отказу;
  повтор корректно говорит о намерении.
- GM18: оба не обходят закрытые дверь и сундук, не объявляют спасение грамот.
- GM28: сохраняет провал договора и возможность спасать оригиналы, не
  превращает неуспех в победу. Три предложения длиннее заданных 1–2;
  жесты курьера являются художественными деталями, не подтверждёнными событиями.

DeepSeek V4 Pro остаётся кандидатом, но готовой заменой считать его рано:
свободная INT-проверка и проверка условий удались, согласованность текста,
плана и предварительной речи требует исправлений. Пользовательской приёмки нет.
