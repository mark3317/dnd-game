## Игровое демо: «Затопленный архив»

ИИ-ведущий использует **DeepSeek V4 Pro** (технический ID `deepseek-v4-pro-0813`) через OpenAI-совместимый API AI STAR.
Автоматический кэш провайдера работает без дополнительных параметров запроса; JSON и последствия
по-прежнему проверяются сервером. Это текущий выбор от 16.11.2026; упоминания GPT Luna
и её замеры ниже относятся к предыдущей модели. HTTP-ожидание ограничено 20 секундами, подключение —
5 секундами. Автоповторов запросов нет; при ошибке ход и ресурсы сохраняются.
Для измерения скорости текущей модели: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-claude-server.ps1 -ProbeCurrent`.
Команда делает ровно два запроса (диалог/свободный план) и печатает только безопасные
метрики при доступном сервисе. В проверке 15.11.2026 получены 3,7 и 15,3 с;
задержка сервиса может меняться. Текущая недоступность описана ниже; повторять
пробу до изменения доступности не нужно.

На macOS/Linux после `./gradlew :server:installDist` запускайте
`python3 scripts/start-ai-server.py`. Ключ храните в игнорируемом
`server/claude.local.json` либо в `ANTHROPIC_API_KEY`; отслеживаемый
`server/claude.local.example.json` — только пустой шаблон. Загрузчик передаёт ключ
окружением серверному процессу, не Gradle и не аргументами командной строки.
Имена `claude.local.json`, `DND_CLAUDE_*` и `ANTHROPIC_API_KEY` сохранены ради
совместимости загрузчиков; они не означают использование Claude.
Упоминания Claude в датированных проверках ниже относятся к прежней модели,
их результаты не доказывают качество текущей GPT Luna.

16.11.2026 начатая контрольная серия текущей модели не получила ответов: 14 попыток
завершились транспортным timeout примерно за 5 сек, ещё одна остановлена. Из разрешённых
150 попыток начато 15, остаток 135. Независимая диагностика указывает на недоступность
TCP 443 текущего AI STAR с этого хоста; это не доказательство ошибки авторизации,
отсутствия модели или качества её ответов. Новые запросы до изменения доступности
не запускаются. Runner останавливается после двух последовательных сетевых отказов
либо сразу при 401/403, а оставшиеся случаи явно отмечает not_run; повторов нет.
Подробности и ограничения — [отчёт надёжности](docs/demo-reliability-progress.md).

В списке историй пока доступен только **«Затопленный архив · полное демо»**:
исследование, проверки, сетевой бой, лечение, пролог и эпилог. Ранние прототипы
архива и маяка скрыты из выбора.

Главное меню: **Создать игру**, **Присоединиться к игре**, **Персонаж**, **Настройки**
и **Выход** на Desktop. У меню собственный рисованный фон, анимированная камера,
подсветка пунктов, переходы и встроенные шрифты с кириллицей. Выбор карточки истории
создаёт сетевую комнату после ввода имени/адреса сервера. В подготовке можно скопировать
приглашение, выбрать или создать героя, дождаться 2–4 участников и начать после
подтверждения персонажей всеми игроками. Локальная игра и учебный бой — в настройках.

**Настройки** объединяют отдельную громкость и выключение музыки, озвучки и эффектов/окружения,
размер субтитров (80–140%, с предпросмотром) и движение камеры. Они сохраняются
на устройстве и доступны также из подготовки группы, меню приключения и боя.
Кнопка «Включить звук» повторно запускает воспроизведение, если браузер его заблокировал.

Создание персонажа снова включено. Собственного героя можно редактировать, в том числе
менять аватар: доступны 16 портретов для сочетаний расы и класса. Облик сохраняется
на устройстве и передаётся по сети. Генерация аватара и загрузка фото пока
не подключены. В бою используются классовые наборы поз.
Фон, исходный атлас, промпты и источники шрифтов: [пак меню](assets/visual/menu-v1/README.md).

Истории начинаются покадровым прологом рассказчика и заканчиваются эпилогом с итогами:
затемнение, плавная смена иллюстраций, медленное приближение/движение камеры.
Кадры и постепенные субтитры синхронизированы сервером, кнопок просмотра нет. После эпилога — главное меню. В финале рассказаны
авторский исход и подтверждённые факты прохождения. Реплики рассказчика доступны
текстом и через пробную озвучку; при отказе голоса остаётся текст.
Добавлены четыре готовых кадра для архива и маяка:
[файлы и промпты](assets/visual/cinematics-v1/README.md).

Музыка играет в меню, прологе, исследовании, проверках, бою и финале; трек меняется
с плавным затиханием и нарастанием. Общие «Настройки» открывают громкость/выключение, параметры
сохраняются на устройстве. Три MP3 входят в сборку и не требуют интернета.
Авторы, CC0-лицензии, источники и контрольные суммы —
[музыкальный пак](assets/audio/music-v1/README.md). В браузере при первом запуске
может понадобиться «Настройки» → «Включить звук». Позиция саундтрека между клиентами
не синхронизируется. Подключена пробная озвучка Qwen3-TTS: готовые фразы входят
в сборку, новые генерирует локальный GPU-сервис. Генерация уникальных картинок
финала пока не подключена; просмотр использует готовые изображения.

Сюжетные проверки сопровождаются полноэкранным кубиком поверх прозрачного затемнения текущей сцены. Бой начинается с плавной заставки «Бой начинается», затем показывается своя инициатива (локально — первого героя) и с анимацией появляется общая очередь. Вход и выход боевых вставок, смена поз, раскрытие результата и переход между приключением и картой плавные; управление открывается после завершения выхода последней вставки. Атаки, помощь, повязки, лечение и защита проигрываются на фоне двора с боевыми аватарами: действующий слева, цель справа; кубика в этих вставках нет, реальные броски и последствия раскрываются после действия. Движение всех существ анимируется по маршруту. Пак фонов и шести наборов поз: [изображения и промпты](assets/visual/combat-v1/README.md).

Дважды нажмите свободную клетку для движения или врага для атаки. Обычное нажатие выбирает клетку сразу, без ожидания второго клика. Доступные клетки и активный герой подсвечиваются только в свой ход; отказ объясняется под нажатием. Обычное нажатие существа открывает подходящие ему действия: враг — атака/боевой приём, союзник — помощь/повязка/классовое лечение, себя — защита/повязка/самолечение. После расхода действия и перемещения ход завершается автоматически. Готовые Рин, Мира, Бран и Лада и собственные герои доступны для группы из 2–4 игроков. Подробности и оставшиеся этапы — в [боевом плане](docs/combat-implementation-plan.md).

В выборе приключений появился **«Затопленный архив · полное демо»**. Локально он выбран по умолчанию; в сетевом лобби его выбирает создатель комнаты. Выберите героев для 2–4 игроков и начните историю. Подготовка → оборона двора → спасение оригиналов или договор о копиях → законченный эпилог. Подробности и маршрут проверки: [демо](docs/archive-demo.md).

Бой подключён к этой истории и работает локально и по сети. Он использует выбранных героев, их классы, характеристики, здоровье и повязки. Сервер выполняет броски и ходы врагов; после победы история продолжается с оставшимися ресурсами, после поражения показывает финал. Готовые фоны архива и портреты входят в сборку. Генерация картинок во время игры пока не подключена. Бесплатная озвучка Qwen включается в общих настройках.

### Пробная озвучка Qwen3-TTS

Ведущий сам разделяет свободный ввод на речь и действие в рамках одного запроса.
Реплики звучат голосом героя, действия — голосом рассказчика от третьего лица.
Смешанный ввод воспроизводится по частям в исходном порядке; исходный текст команды
напрямую не озвучивается. Короткий блок подачи приходит первым по SSE: после проверки
он сразу передаётся в TTS, пока ведущий ещё готовит остальной ответ. Отдельного запроса
классификации нет; намерение не подтверждает успех действия. Новые длинные ответы разбиваются на фрагменты:
следующие голоса готовятся в фоне, текст раскрывается при воспроизведении своего
фрагмента. При ошибке/ожидании синтеза свыше 15 секунд остаётся последовательный
текст. Готовые записи не дробятся заново. Протокол рабочей версии **16**: обновите сервер и клиенты
вместе. Общий серверный координатор один раз готовит фрагменты, публикует их порядок,
файлы и расписание, принимает отдельные READY/FINISHED/FAILED и ограничивает ожидание.
Ввод и переходы пролога, боя и эпилога ждут завершения общей презентации; ошибка голоса
оставляет текст. Между аудиофрагментами нет отдельного сетевого барьера.
Ready у Desktop-плеера не означает полного буфера или точного старта аудиосэмплов.
При восстановлении iOS/Wasm текущая реплика продолжается текстом, следующая — по
общей очереди; реальная синхронность на устройствах требует живой проверки.
Варианты маскировки оставшихся пауз и границы
применения вставок рассказчика — в [медиа-плане](docs/media-implementation-plan.md#задержки-разговора-конвейер-от-15112026).

В «Затопленном архиве» подготовлены 22 записи пролога, финалов, описаний мест
и стандартных ответов NPC. Новые реплики игроков, NPC и рассказчика генерируются
на ПК с NVIDIA; телефоны и браузеры воспроизводят WAV, модель на них не запускается.
Голоса закреплены за персонажами. Громкость и выключение речи доступны в общих
**настройках**, в том числе во время приключения и боя.

Первичная установка: `scripts/setup-qwen-tts.ps1`. Затем
`scripts/start-qwen-game-test.ps1` запускает тестовый игровой сервер на порту
18082 и при необходимости отдельный GPU-сервис на loopback:8091. Подключение:
`ws://localhost:18082`; на другом устройстве — LAN-адрес ПК с тем же портом.
Готовые записи работают без сервиса; для новых фраз ПК должен оставаться включён.
Локальная игра на этом же ПК обращается непосредственно к loopback:8091.

По умолчанию тест использует готовые ответы NPC. Для обычного ИИ-ведущего есть
`scripts/start-qwen-game-test.ps1 -WithGameMaster`: он использует прежний штатный
скрипт и локальную конфигурацию ИИ-ведущего, не меняя провайдера текста. Уже работающий
сервер с той же конфигурацией сначала нужно остановить; изменения сервера сами
по себе не обновляют запущенный процесс.

Первый запуск скачивает веса и прогревает CUDA Graphs. На RTX 5070 новые тестовые
реплики длительностью 5,9 с стали доступны за 2,3–3,8 с. Это буферизация коротких
фрагментов целиком, а не поток PCM во время синтеза. Эти ранние замеры не проверяют
нынешний координатор комнаты: его серверные/JVM/TCP проверки и компиляция Android,
Wasm и iOS прошли отдельно, а GPU, качество голосов и живой многоплатформенный звук
ещё требуют проверки. Субтитры активной озвучки следуют позиции плеера; общий
визуальный график сохраняется сервером. Подключившийся клиент не запускает старые
реплики. Для браузера используется CORS Ktor: локальные адреса сервера разрешены,
внешние адреса страниц добавляются через `DND_WEB_ORIGINS` (через запятую).

[Прослушать образцы](assets/audio/speech-qwen-v1/preview.html),
[источники, инструкции и замеры](assets/audio/speech-qwen-v1/README.md).

Протокол рабочей версии — **16** (выданный ранее checkpoint14 остаётся на 14): сервер и клиенты нужно обновить вместе. Особые текстовые действия в бою, генерация портрета своего героя и эмоции пока не реализованы. Координатор генерируемой речи реализован, но фактическое качество и синхронность на устройствах ещё не подтверждены. Длительность 40–60 минут остаётся целью и требует игрового замера.

После игрового теста экран перестроен вокруг сцены: аватары стоят поверх фона, снизу только последняя реплика. «Герои», «Текст», «Меню» и «Действия» открывают боковую панель. Рассказчик описывает события, NPC говорят от первого лица; правила и численные результаты вынесены из речи в интерфейс и журнал. Для готовых механических команд запрос к модели не нужен. Для свободных действий промпт и контекст сокращены; текущая GPT Luna (`gpt-6-luna`) использует `reasoning_effort=none`. Следующий ввод/ход открывается после полного отображения реплик, включая дополнительное описание результата. Субтитры рассказчика, NPC и игроков появляются постепенно в едином стиле без плашки; длинные фразы показываются по частям. В сцене остаются активный герой и местный NPC, поле ввода плавно появляется и скрывается.

Сравнение моделей для быстрого ответа и корректных планов: [исследование API](reports/Модели%20для%20быстрого%20игрового%20ведущего.md). Рекомендации в нём предварительные, провайдер автоматически не меняется.

План боевой системы и адаптивного интерфейса: [боевой план](docs/combat-implementation-plan.md). Согласован выбор основных боевых действий через интерфейс с ориентиром на упрощённые BG3/XCOM; текстовая импровизация — отдельное особое действие. Демо использует текущие правила прототипа; окончательный баланс остаётся открытым.

Интерактивный локальный прототип доступен через **«Настройки → Учебный бой»**. Двойное нажатие клетки перемещает, двойное нажатие врага атакует; обычное нажатие выбирает цель и контекстные действия. «Завершить ход» пропускает остаток ресурсов. Только в учебном бою на компьютере кнопка «Телефон» включает узкую компоновку 390 dp. Это учебная сцена без сети и ИИ; сюжетный бой доступен в полном демо.

В прототипе есть общая инициатива героев/врагов (`d20 + ловкость`), атаки против КЗ, кости урона, промах на 1 и крит на 20. Перед выполнением показаны шанс и формулы, после — реальные броски в журнале. Четыре класса имеют разные приёмы: Второе дыхание, Огненный всплеск, Точный выстрел и Ободряющее слово; способности и расход действий упрощены. Противники автоматически перемещаются и атакуют с учётом преград и дальности. Точные текущие правила и ограничения — в [боевом плане](docs/combat-implementation-plan.md).

В боевом прототипе действие **«Повязка»** восстанавливает 4 здоровья себе или соседнему союзнику за действие и предмет; у каждого героя одна повязка на сцену. Выбывшего можно поднять один раз за бой, после повторного выбывания он ждёт завершения боя. После победы у всех героев минимум 4 здоровья, повязки не пополняются. На поле видны выбывшие, в очереди — запас повязок и статус поднятия. «Заново» полностью сбрасывает учебную сцену. Лечебные классовые приёмы демо действуют только на героев на ногах.

План визуальной сцены, паков историй/аватаров, озвучки и редких иллюстраций: [медиа-план](docs/media-implementation-plan.md). Подготовлен [первый визуальный пак архива и готовых героев](assets/visual/README.md), доступен [интерактивный просмотр](assets/visual/preview.html). Его фоны, NPC и нейтральные портреты готовых героев подключены к полному демо. [Стартовый CC0-пак звуков](assets/audio/starter-v1/README.md) содержит 35 файлов с источниками и лицензиями. Из него подготовлены и подключены восемь эффектов/окружений: [игровой пак](assets/audio/game-v1/README.md), отдельные настройки громкости и включения. Эффекты следуют подтверждённым событиям, тихий фон доступен в разговорном подвале. Это реализованный срез, ожидающий проверки shared и слуховой/визуальной приёмки; полноценная звуковая библиотека и генерация во время игры пока не завершены.

## Формат и настроение игры

Совместная ролевая игра с друзьями по сети, в которой нейросеть выполняет роль гейммастера. Игра строится вокруг отдельных законченных историй на 40–60 минут. Это целевая длительность сессии, определяющая объём и темп приключения. Также планируются кампании из 3–5 таких историй — отдельных глав одного большого сюжета.

Истории рассчитаны на 2–4 игроков, не считая ИИ-гейммастера. Игрок сможет создать собственного персонажа и проходить им разные истории; Рин, Мира и Бран останутся готовыми вариантами для быстрого старта. Сценарии должны поддерживать разные составы героев без обязательного присутствия конкретного готового персонажа.

Перед стартом доступны создание своего персонажа и выбор готового героя: класс, раса, предыстория и распределение набора 15, 14, 13, 12, 10, 8. Подробные правила и ограничения описаны ниже.

Настроение игры — весёлое, увлекательное и вовлекающее, по впечатлению от «Подземелий Чикен Карри». Игроки могут неформально общаться, шутить, импровизировать и совершать действия, немного выбивающиеся из стилистики мира. Гейммастер подхватывает импровизацию, старается сохранять общий сеттинг и ход сюжета и мягко возвращает внимание к приключению, оставляя игрокам свободу решений. Юмор сочетается с последовательными правилами и последствиями действий.

Это направление разработки. Текущие два демонстрационных сценария не подтверждают длительность 40–60 минут; кампании и перенос состояния между главами ещё не реализованы. Постоянный контекст и принятые решения описаны в [AGENTS.md](AGENTS.md).

Созданные герои сохраняются на устройстве и доступны в разных историях; сетевые комнаты и локальная группа поддерживают 2–4 игроков. Развитие, облачная синхронизация и перенос последствий между историями ещё не реализованы.

## Создание и выбор персонажа

Создание собственного героя доступно из главного меню и подготовки группы. Для быстрого старта есть четыре готовых профиля: Рин, Мира, Бран и Лада. Сохранённые герои доступны в библиотеке; генерация индивидуального аватара пока не подключена.

В сетевом лобби каждый выбирает своего героя; при входе предлагается свободный готовый персонаж.
Предложение не резервирует героя: если другой игрок выбирает его первым, сервер меняет местами
только ещё не выбранные предложения. Явно выбранного персонажа забрать нельзя. Каждый игрок должен явно подтвердить
предложенного или выбранного героя; это условие проверяют и интерфейс, и сервер.
До старта его можно заменить сохранённым или новым героем. Имена героев внутри группы должны
различаться без учёта регистра. Выбор, изменение сюжета и старт выполняются сервером последовательно:
если история уже началась, смена героя отклоняется. Переподключение восстанавливает выбор.
В локальном режиме перед стартом выбирают сюжет и героев каждого из 2–4 участников.

Редактор позволяет задать имя до 24 символов, описание до 240 символов, класс, расу,
предысторию и распределить шесть разных чисел 15, 14, 13, 12, 10, 8. Выбор занятого числа
меняет его местами с прежним владельцем, сохраняя общий набор. Бонус характеристики равен
округлённому вниз `(значение − 10) / 2`; здоровье — `12 + бонус телосложения` (11–14).

| Класс | Проверки со специализацией +1 |
|---|---|
| Воин | Физическая сила; сопротивление физической нагрузке |
| Плут | Вскрытие замков; механические ловушки |
| Маг-исследователь | Магические явления; устройства и письменные загадки |
| Бард | Убеждение сотрудничать; выступление перед публикой |

| Раса | Талант: +2 перед подходящим броском, один раз за историю |
|---|---|
| Человек | Общий язык: сотрудничество с ещё незнакомым герою NPC |
| Эльф | Острые чувства: зрение и слух |
| Дварф | Знаток ремесла: каменные и металлические конструкции |
| Полурослик | Ловкий шаг: равновесие и тесные проходы |

Для человеческого таланта сервер хранит знакомство каждого героя с NPC по ID сценария:
разговор, получение совета хранителя и состоявшаяся проверка сотрудничества отмечают контакт.
Отмена проверки, ошибка и комментарий не отмечают знакомство. Разговор другого героя
не делает NPC знакомым всему отряду. Знакомства сбрасываются с историей.

| Предыстория | Проверки со специализацией +1 |
|---|---|
| Солдат | Военные порядки, знаки и тактика |
| Ремесленник | Ремонт |
| Архивист | Поиск и сопоставление документов |
| Торговец | Торг о цене и условиях обмена |
| Моряк | Узлы, такелаж и лодки |
| Артист | Отвлекающее представление |

Класс и предыстория не складываются: максимум +1 специализации. Расовый талант добавляет
ещё +2; максимальный стартовый бонус к d20 равен +5. Перед броском показаны бонусы и
отдельная кнопка броска с талантом. Ресурс расходуется только после действительного броска,
включая провал; отмена сохраняет его. Журнал хранит серверную разбивку бонусов в RollResult.
Класс не запрещает действия другим героям. Полезные заклинания вне боя ещё не реализованы; боевые приёмы доступны в полном демо архива.

Области проверки заданы данными CheckDomain. Готовые действия размечены сценариями;
для свободного плана GPT Luna предлагает области, сервер проверяет их по разрешённым
checkDomains условий фактов/маршрутов и выбранной характеристике. Необоснованные численные
бонусы модель назначить не может. Смысловое соответствие свободного способа допустимой
области по-прежнему зависит от модели. В текущих сюжетах нет проверок всех специализаций:
например, обычный безопасный осмотр не получает кубик ради эльфийского таланта.

Рин, Мира и Бран используют тот же CharacterProfile, проверку набора и расчёт здоровья:

| Герой | Класс / раса / предыстория | СИЛ / ЛОВ / ТЕЛ / ИНТ / МДР / ХАР | Здоровье |
|---|---|---|---|
| Рин | Плут / эльф / моряк | 12 / 15 / 13 / 10 / 14 / 8 | 13 |
| Мира | Маг-исследователь / дварф / архивист | 8 / 12 / 10 / 15 / 14 / 13 | 12 |
| Бран | Воин / человек / солдат | 15 / 10 / 14 / 8 / 12 / 13 | 14 |

Профиль отделён от здоровья, предметов, места и потраченного таланта партии. Новая история
и перезапуск восстанавливают здоровье и талант и выдают стартовое снаряжение выбранного
сценария. Клиент передаёт профиль, сервер проверяет набор и сам строит игрового героя;
произвольное здоровье, модификаторы или предметы клиент назначить не может.

Библиотека хранит до восьми своих героев через Multiplatform Settings 1.3.0: Android
SharedPreferences, iOS NSUserDefaults, Desktop Java Preferences, Wasm localStorage.
Это локальное хранение, без аккаунта, обмена между устройствами и сохранения партии.
Ошибки чтения не перезаписывают сохранённых героев; ошибки записи показываются игроку.
Удаление профиля из библиотеки не меняет выбранного героя текущей комнаты.
Протокол персонажей первоначально был повышен до 7; текущие исходники используют протокол **16**, сервер и клиенты нужно обновить вместе.

15.11.2026 прошли 132 теста: game JVM (69), server (59), shared JVM (4).
Проверены одинаковые ограничения готовых/своих героев, предел бонусов всех сочетаний,
расход и отмена таланта, знакомство с NPC, локальная группа, сохранение профилей,
выбор независимо от порядка входа и защита чужого выбора. Настоящий TCP с четырьмя
KMP-клиентами проверил своего героя, переподключение перед броском и общий результат
с расовым талантом. Собраны Desktop classes, Android debug, production Wasm и серверный
installDist. Новые проверки с реальным Claude и визуальная проверка UI не выполнялись;
iOS на Windows не проверялся. Это проверка механических ограничений, не гарантия
равной полезности всех сочетаний в каждой истории.

## Project structure

- `game` — shared game state, rules, diagnostics, serializable network protocol and Ktor client, without Compose.
- `server` — standalone JVM Ktor WebSocket server depending on `game`.
- `shared` — Compose UI, resources, ViewModels and network screens. Depends on `game` and produces the `Shared` framework for iOS.
- `androidApp` вЂ” Android application, manifest, launcher resources, and `MainActivity`. Uses AGP's built-in Kotlin support.
- `desktopApp` вЂ” JVM application entry point, Compose Hot Reload, and native distribution packaging.
- `webApp` вЂ” browser entry point and HTML shell for Kotlin/Wasm.
- `iosApp` вЂ” Xcode application and SwiftUI host for the shared UI.
- `gradle/libs.versions.toml` вЂ” dependency and plugin versions.

Application modules depend on `shared`. Only application modules define executable entry points for Android, Desktop, and Web. The iOS UIKit bridge remains in `shared` so Swift can call it from the generated framework.

## Requirements

Use JDK 21 for Gradle and Desktop development (including Compose Hot Reload). Install Android SDK 37 to build Android. Android minimum SDK is 24; target SDK is 36. Compose UI 1.12.1 and Lifecycle 2.11.0 require compile SDK 37.

For iOS, use macOS and Xcode 26.4. Set the signing team in the Xcode project before running on a device.

The web application requires a browser with WasmGC support. This project targets Kotlin/Wasm only, without a JavaScript fallback.

Commands below use the Windows wrapper. On macOS/Linux, replace `.\gradlew.bat` with `./gradlew`.

```powershell
# Android debug APK
.\gradlew.bat :androidApp:assembleDebug

# Desktop
.\gradlew.bat :desktopApp:run

# Desktop with Compose Hot Reload
.\gradlew.bat :desktopApp:hotRun
```

## Игра по сети

1. На компьютере с JDK 21 запустите сервер: `.\gradlew.bat :server:run`. Он слушает TCP-порт 8080 на всех интерфейсах. Проверка доступности: `http://localhost:8080/health`.
2. Запустите Desktop, Android, iOS или Web-клиент. Введите имя и адрес сервера: на том же ПК `ws://localhost:8080`, на других устройствах `ws://<LAN-IP компьютера>:8080`. Для Android-эмулятора адрес хоста обычно `ws://10.0.2.2:8080`.
3. Один игрок нажимает «Создать комнату» и сообщает друзьям адрес сервера и шестизначный код. Остальные вводят код и нажимают «Присоединиться».
4. История выбирается при создании комнаты; в текущем меню доступно полное демо архива. Каждый участник выбирает и подтверждает готового или своего героя. Когда подключены 2–4 игрока и все подтвердили выбор, интерфейс открывает ведущему «Начать приключение». Каждый отправляет действия и бросает кубик только в свой ход; состояние и результат броска одинаковы у всех. После старта сменить сюжет или героя нельзя; перезапуск сохраняет выбор. Серверная проверка подтверждения пока неполна — см. [найденные расхождения](docs/development-plan.md#ограничения-и-найденные-расхождения).
5. В протоколе 16 при обрыве вся действующая партия ждёт возвращения игрока на паузе. Нажмите «Подключиться снова», после перезапуска приложения — «Вернуться к партии». Пропустить отсутствующего нельзя. Подтверждённый выход любого участника завершает партию для всей группы; выход из лобби освобождает место.

Для другого порта задайте `DND_SERVER_PORT` перед запуском. Самостоятельный дистрибутив сервера без UI:

```powershell
.\gradlew.bat :server:installDist
# Windows, JAVA_HOME указывает на JDK 21:
.\server\build\install\server\bin\server.bat
```

На Linux/macOS запускайте `server/build/install/server/bin/server`.

Друзьям из интернета нужен доступный им адрес сервера. Типичная схема — JVM-сервер за HTTPS reverse proxy, который передаёт WebSocket Upgrade на `127.0.0.1:8080`; клиенты вводят `wss://имя-сервера`. Текущий `/play` находится в корне адреса; префиксы URL не поддерживаются. Сервер здесь не развёрнут в интернете, автоматической настройки роутера/firewall или relay нет. Для LAN входящий TCP-порт должен быть доступен устройствам.

Android debug допускает `ws://` для разработки; release используйте с `wss://`. У HTTPS-версии Web-клиента также должен быть `wss://` сервер. На iOS добавлены описание доступа к локальной сети и `NSAllowsLocalNetworking`; запуск и сетевые разрешения нужно отдельно проверить на Mac/устройстве.

Ограничения прототипа:

- Комнаты и прогресс хранятся в памяти сервера. Его перезапуск сбрасывает игру. В протоколе 16 действующие и ожидающие комнаты не удаляются по времени отключения; очистка после 30 минут касается пустых лобби и завершённых комнат.
- Протокол 16 хранит на устройстве приватный ключ восстановления подключения, включая адрес сервера; это позволяет вернуться после перезапуска клиента. История и состояние мира на диск не сохраняются. Ошибка хранилища показывается игроку. После начала нельзя присоединиться новым героем.
- Сервер передаёт последние 200 записей журнала. Полный журнал текущей партии остаётся в памяти сервера.
- Автоматического повтора действий нет: после обрыва клиент получает актуальный снимок. Сервер выполняет броски и проверяет владельца хода/проверки; ID игрока определяется подключением.
- Учётных записей, базы данных и постоянных сохранений пока нет. Код комнаты — приглашение, токен восстановления — приватный доступ к своему персонажу.
- Комнаты поддерживают 2–4 участников; баланс и разнообразие специализаций требуют дальнейших игровых проверок.

Сеть использует [Ktor 3.6.1](https://ktor.io/docs/client-websockets.html), [рекомендованный набор движков KMP](https://ktor.io/docs/client-engines.html) и kotlinx.serialization. Серверные тесты проверяют очередь, владельца броска, повторные команды, возврат в комнату, отключения и реальную TCP-синхронизацию нескольких KMP-клиентов.

## Adventure prototype

The main menu opens game creation, joining, character editing and settings. Local play and the combat tutorial are in settings. Both local and network menus offer **The flooded archive · full demo**; the earlier lighthouse and archive remain in the internal catalog for regression tests. The scene shows the active hero and local NPC over a prepared background; character sheets, history, actions and rules open in side panels. Each hero has independent health, modifiers, inventory and location.

The local narrator is scripted. Network rooms optionally use the configured AI STAR model (`deepseek-v4-pro-0813` by default); otherwise they use the scripted narrator. Local progress lives in app memory; network progress lives on the running server. Starting over resets the episode after confirmation.

Story checks use d20 + an ability modifier + applicable expertise and an optional racial talent against a difficulty (a tie succeeds), without automatic critical outcomes. The full demo has eight shared checks; the earlier lighthouse/archive use three/four. In scripted play completed actions advance to the next player; in AI play the narrator can retain or change the speaker. Actions requiring dice finish after the roll. Inspection, conversation and safe actions do not spend checks; comments and clarifications retain the turn. Cancelling before a roll, unsupported text and unavailable actions keep the current turn. Completing a goal on the last check takes priority over the timeout ending. Combat has separate initiative, action/movement resources, attack rolls and critical hits. These are demo rules, not the final balance specification.

Game rules live in `game` (`adventure` and `combat`); UI and ViewModels remain in `shared`. The server owns state, player identity and dice. Clients send intent with turn/check IDs; stale and repeated commands are rejected. Character creation, device-local profiles, network combat, prepared images, music and experimental Qwen speech are implemented. A room coordinator for dynamic speech is implemented and passed server/JVM/TCP checks and Android/Wasm/iOS compilation; actual voice quality and device synchronization still need live validation. Eight CC0 sound effects/ambience assets and separate settings are implemented, awaiting shared verification and human QA. Persistent adventure saves and generated avatars/event illustrations remain future work.

## Сценарии и общий движок

| Сюжет | Места и задача | Пути к цели |
|---|---|---|
| Погасший маяк | Берег и фонарная комната; предупредить паром | Починить привод инструментами или подать сигнал фонарём; верёвка и помощь хранителя облегчают проверки |
| Затопленный архив | Зал, двор и подвал; сохранить земельные грамоты | Открыть дверь и сундук, защитить оригиналы тканью; либо прочитать опись и договориться с курьером о копиях |

Определения сюжетов находятся в `game/src/commonMain/kotlin/ru/markn/dnd/adventure/Scenarios.kt`.
`ScenarioDefinition` задаёт названия и описания мест, каталог предметов, факты и требования к ним,
переходы, начальное снаряжение, запас проверок, действия-подсказки и финалы. Это сериализуемые
Kotlin-данные внутри приложения; внешнего загрузчика сценариев, редактора и скрытой памяти NPC пока нет.
ID мест, предметов, фактов, действий и финалов — строки из выбранного определения. Инвентарь
хранит ID, UI отображает названия из каталога сценария.

`AdventureEngine` и `SceneRules` общие для обоих сюжетов: проверяют ход, владение предметом,
совместное расположение при передаче, доступность перехода, обязательные факты, минимальную
сложность, расход предмета и условия финала. Обе ветки плана проверяются атомарно до броска.
Факты могут открыть переход или действие, а существующие факты — понизить минимальную сложность.
Сюжетных ветвлений по ID маяка или архива в движке нет. Готовые действия также превращаются
в те же `SceneActionPlan`, что и свободные предложения ИИ.

GPT Luna получает только определение выбранного сюжета и его актуальное состояние; JSON schema
содержит только его допустимые ID. Предметы, факты и цели другого сюжета отклоняются. Все
пока поддерживаемые типы последствий прежние: move, transfer, fact, damage. Сложность свободного
броска 8–18, урон только в провальной ветке и не более 3 суммарно. Это общий профиль двух прототипов.

Примеры архива: «Читаю номера грамот в описи», «Пытаюсь открыть замок двери отмычками, изучив
механизм», «Передаю ткань Мире», «Убеждаю курьера доставить копии по найденным номерам».
Дверь подвала должна быть открыта до перехода, сундук — до спасения оригиналов; копии требуют
найденных номеров и разговора во дворе. Неудача проверки расходует время и оставляет возможность
повторить попытку или сменить путь, пока общий запас не исчерпан.

Автоматические проверки включают оба финала архива, поражение и победу на последней проверке,
передачу/расход снаряжения, недопустимые ID и закрытые переходы. TCP-тест с двумя KMP-клиентами
проходит архив через свободные планы, переподключается перед броском и перезапускает тот же сюжет.
MockEngine проверяет контекст/schema архива через настоящий клиент Koog без расхода API-токенов.

## Настройка сетевого ИИ-ведущего

Провайдер — [AI STAR](https://ai.starimg.ru/help). Сервер использует клиент [Koog 1.3.0 от JetBrains](https://docs.koog.ai/prompts/llm-clients/).
Адрес и модель настраиваются; по умолчанию выбрана `deepseek-v4-pro-0813` через OpenAI-совместимый API AI STAR (`/v1/chat/completions`). Используется прежний ключ; имена `ANTHROPIC_API_KEY`, `DND_CLAUDE_MODEL` и локального файла сохранены для совместимости. Модели Claude по-прежнему используют Anthropic API.
Доступность модели для конкретного ключа и поддержка структурированных ответов требуют проверки реальным запросом.

Для локальной пробы на Windows запустите из корня репозитория:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-claude-server.ps1
```

Лаунчер создаёт `server/claude.local.json` из `server/claude.local.example.json`, если файла ещё нет.
Впишите свой ключ в `apiKey` локального файла, либо вставьте его в скрытый запрос терминала.
Если `ANTHROPIC_API_KEY` уже задан в окружении терминала, он имеет приоритет, а локальный файл не читается.
Локальный файл исключён из Git; пример с пустым ключом хранится в репозитории. Не присылайте содержимое
заполненного файла в чат. Шаблон настроен на AI STAR и `deepseek-v4-pro-0813`; существующий локальный файл сохраняет свои значения.
Скрипт находит JDK 21 через JAVA_HOME/PATH или стандартные каталоги JDK, собирает сервер при отсутствии
дистрибутива и запускает его напрямую, передавая ключ только через окружение Java-процесса.
Для пересборки используйте параметр `-Rebuild`. Остановка — Ctrl+C; постоянные переменные окружения не меняются.
Игровые клиенты подключаются к `ws://localhost:8080`. Для текущего сетевого сценария нужны два клиента:
один создаёт комнату, другой входит по её коду; «Локальная игра» в настройках использует сценарного ведущего без обращения к ИИ.

Перед вводом ключа соберите `:server:installDist`. Затем задайте переменные **на компьютере с сервером** и запускайте готовый дистрибутив без Gradle. Пример PowerShell с вводом ключа без его записи в историю команд:

```powershell
$env:ANTHROPIC_API_KEY = [System.Net.NetworkCredential]::new('', (Read-Host 'AI STAR API key' -AsSecureString)).Password
$env:DND_CLAUDE_BASE_URL = 'https://ai.starimg.ru'
$env:DND_CLAUDE_MODEL = 'deepseek-v4-pro-0813'
.\server\build\install\server\bin\server.bat
```

На удалённом сервере задайте эти переменные в окружении службы, которая запускает серверный дистрибутив.
Base URL — только HTTPS origin, без `/v1`, query, логина и пароля; клиент добавляет `/v1/chat/completions`
для GPT или `/v1/messages` для Claude. Авторизацию GPT добавляет Koog; для Claude используются
`x-api-key` и `Authorization: Bearer`. Перенаправления HTTP отключены.
Не сохраняйте ключ в репозитории или настройках распространяемых клиентов. Без `ANTHROPIC_API_KEY` сеть работает со сценарным ведущим.
После изменения конфигурации перезапустите сервер: текущие комнаты при этом теряются.
Текущий протокол версии **14**: сервер и клиенты необходимо обновить вместе. Статус ожидания различает
разбор действия, реакцию на бросок и эпилог; сохраняется выбор следующего героя при проверке.

### Общение и передача слова

Разделы с датированными прогонами Claude ниже сохраняют историю разработки. Текущие
модель и протокол указаны выше; `maxTokens=1200`, HTTP-таймаут 20 с и подключение 5 с
сочетаются с внешним ограничением задания комнаты 45 с. Сохраняются максимум четыре
AI-задания одновременно и отсутствие автоматических повторов. Готовые механические
команды и обычные проверки используют сценарное описание без модели; для свободных
планов/финала возможен отдельный запрос описания подтверждённого результата.

В ИИ-режиме пишет текущий игрок. Можно неформально общаться, шутить, обсуждать план и задавать
вопросы о правилах в том же поле. Ведущий отвечает коротко и живо, подхватывает юмор, старается
сохранять сеттинг и мягко возвращать внимание к приключению. Современная отсылка сама по себе
не создаёт новые предметы или возможности мира. Комментарий и уточнение сохраняют ход и ресурсы.

Ведущий различает общение и намерение действовать: «Ну мы и спасатели, сначала бы пообедать» —
комментарий, «Осматриваю берег как строгий ревизор» — осмотр, шутливый вопрос хранителю — разговор
с NPC. Риск и последствия зависят от действия, а не от серьёзности формулировки.

После игрового действия GPT Luna выбирает `nextPlayerId` из участников: тот же герой продолжает
связанный эпизод или слово получает другой, когда это логично. Обязательной круговой очереди нет;
промпт просит учитывать участие всей группы. Сервер проверяет ID и обновляет идентификатор хода
после завершённого действия, даже если герой остался тем же. Выбор следующего героя при проверке
фиксируется до броска и применяется после результата; отмена до броска сохраняет текущего героя.
Неизвестный ID и передача слова другому через комментарий отклоняются без изменения состояния.

Кнопка «Передать ход» и пропуск отключённого героя переключают на следующего в списке.
Без ИИ действует прежняя круговая очередь. Отдельного чата вне очереди пока нет.
Каждая отправленная реплика в ИИ-режиме вызывает один запрос к модели, включая шутки и вопросы.
Тесты без ключа проверяют сохранность состояния, выбор героя и синхронизацию клиентов; качество
классификации, юмора и распределения внимания требует отдельной игровой оценки.

### Память участия игроков

В каждой комнате сервер хранит отдельную память участия за текущую партию. В запрос разбора
реплики GPT Luna передаётся неизменяемая сводка `participation`, полученная под тем же Mutex,
что и снимок игры. Она содержит общее число завершённых действий, число действий/бросков каждого
героя, индекс его последнего действия, ожидание в чужих завершённых действиях, число получений
слова, ожидание с последнего фокуса, длину нынешнего блока действий и последние 12 действовавших ID.
Это счётчики действий, не минуты ожидания. Они не восстанавливаются из последних 16 записей
журнала и сохраняют раннее участие независимо от длины журнала и переподключения.

Завершёнными считаются исполненные безопасные действия, осмотр/разговор и выполненный бросок
при любом исходе. Ожидающая проверка ещё не засчитана. Комментарий, уточнение, отмена, недопустимый
план, ошибка API и отменённый запоздалый ответ не увеличивают счётчики. Ручная передача и пропуск
отключённого меняют сведения о фокусе, но не считаются действиями. Реакция и эпилог не добавляют
участия. Перезапуск очищает память; перезапуск самого сервера теряет её вместе с комнатой.

Сводка также показывает подключение и совпадение локации с текущим героем. Отдельно выделены
подключённые герои без единого действия и дольше всего ожидающие. Промпт предлагает давать им
возможность участия в естественной точке завершения эпизода, учитывая место, способности и вещи.
Он допускает продолжение разговора или связанного шага тем же героем и переход через одного
участника. Жёсткого круга, квоты, обязательного минимума и принудительной смены сервером нет.
Новая заявка ещё не включена в сводку; при комментарии и уточнении сохраняется прежний герой.
Доступность указана на момент начала запроса. Два аргумента standalone-вызова GameMaster без
памяти комнаты дают `participation.available=false`, а не вымышленные нулевые счётчики.

передачу от много действовавшей Рин к Мире, исключение отключённого Брана и завершение разговора
с передачей фокуса. После явного выделения ещё не участвовавших героев повторены две пробы:
при действиях 4/1/0 и блоке Рин из трёх действий слово перешло Рин → Бран, через Миру;

запросов ради балансировки нет: сводка входит в прежний запрос разбора реплики.

### Полный пробный проход с тремя участниками

14.11.2026 «Затопленный архив» пройден от старта до финала с реальным Claude через AI STAR,
тремя сетевыми KMP-клиентами и случайными серверными бросками. Реплики всех трёх героев
задавал агент, реагируя на ответы и состояние; это проверка ведения, а не отзыв трёх живых людей.
Модель сама выбирала следующего героя, ручной передачи и указаний дать слово конкретному участнику
не было. Использовался текущий промпт без изменений во время прохождения.

| Герой | Отправленных реплик | Завершённых действий | Бросков |
|---|---:|---:|---:|
| Рин | 6 | 4 | 1 |
| Мира | 5 | 3 | 2 |
| Бран | 5 | 4 | 1 |

В число реплик входит один отклонённый ответ Claude и следующая ручная переформулировка действия;
действия включают завершённые проверки независимо от успеха. Последовательность действий:
Рин ×3 → Мира ×2 → Бран ×4 → Рин → Мира. Все герои повлияли на историю; участие по итогу близко,

### Реакция ведущего на бросок и эпилог

В сетевом режиме GPT Luna получает отдельный запрос для художественного описания свободной проверки или финала.
Готовые механические проверки без выбранного ИИ следующего героя используют сценарное описание результата.
Сначала сервер выполняет бросок, применяет последствия, расходует проверку, определяет финал
и следующего героя и сразу публикует результат. Затем появляется статус «Ведущий описывает результат…».
Если бросок завершил историю, вместо отдельной реакции тот же запрос готовит эпилог со статусом
«Ведущий завершает историю…». Технический результат и исходный сценарный финал сохраняются в журнале.
Без подключённого ИИ-ведущего остаётся сценарное описание.

Контекст содержит подтверждённый бросок с уже вычисленными total/succeeded, фактические изменения
здоровья/инвентаря/мест, новые факты с описаниями, действовавшего героя, использованный предмет,
текущее состояние и точный финал. В памяти комнаты накапливаются подтверждённые механические действия;
для эпилога передаются последние 24 и сводка вклада каждого за всю партию. Намерения и диалоги сами
по себе не считаются совершёнными эффектами. Перезапуск очищает эту историю.

Ответ отдельного контракта содержит только `narration` до 2000 символов. Поля действий, планов,
финала и других изменений отклоняются. Сервер может только дописать текст в журнал; бросок,
числа, факты, позиции, предметы, финал и очередь уже не меняются. Эпилог строится как ретроспектива
подтверждённого итога и вклада героев, с эмоциональным завершением вместо новых событий после финала.

Запрос выполняется вне Mutex с тем же таймаутом 45 секунд и общим пределом четырёх одновременных
обращений без очереди. Пока он идёт, игровые команды ждут; хозяин запроса может нажать «Пропустить
описание». Это отменяет текст, сохраняя бросок и последствия. Переподключение получает текущий статус,
не повторяя API-запрос. Перезапуск и пропуск отключённого героя инвалидируют запоздалый ответ.
Ошибка, таймаут или занятые слоты оставляют подтверждённый результат и безопасное сообщение.
Автоматического повтора нет. На финальный бросок приходится один запрос эпилога, а не два запроса
«реакция + эпилог»; отмена до броска вообще не вызывает реакцию.

### Свободные действия

GPT Luna разбирает свободные способы в пределах выбранного сюжета по общему контракту. Для маяка помимо осмотра, разговора,
подъёма, починки и сигнала, можно передать снаряжение герою рядом, закрепить верёвку для группы,
попросить хранителя помочь, подняться снаружи или спуститься. Например: «Передаю Мире инструменты»,
«Закрепляю верёвку у маяка», «Пробую освободить привод силой с помощью инструментов».

Для нового способа модель предлагает `SceneActionPlan`: намерение, используемый предмет,
необязательную проверку и отдельные списки последствий успеха/провала. Сервер проверяет обе ветки
целиком до броска: известные эффекты и ID, расположение героев, наличие предметов, сложность и урон.
Недопустимый план отклоняется без изменения журнала, очереди или ресурсов; автоматического запроса
исправления к модели нет. Допустимый план проверки закрепляется в `PendingCheck`, показывается
участникам и переживает переподключение. Бросок применяет только выбранную ветку один раз,
без повторного запроса плана. Затем отдельный запрос описывает подтверждённый результат.
Отмена до броска не применяет последствия и сохраняет ход.

Предварительная политика этой сцены: сложность свободной проверки 8–18; подъём требует минимум 10,
уже закреплённая верёвка снижает минимум до 8. Закрепление снимает одну верёвку со снаряжения
и даёт общий постоянный эффект. Помощь хранителя получается у подножия, не суммируется и снижает
минимальную сложность починки/сигнала с 12 до 10. Починка требует инструментов наверху, сигнал — фонаря.
Эти ограничения действуют и для прежних кнопок действий. Передача требует совместного расположения
героев и переносит одну вещь без создания копий. Провал может нанести активному герою суммарно до 3 урона
или только потратить время. Любой бросок расходует одну из трёх общих проверок; безопасное действие
не расходует проверки, а следующий герой определяется ведущим. Успех цели на последней проверке
засчитывается до поражения по времени.

Результат свободного действия описывает сервер по применённым эффектам; произвольная `narration`
модели для плана не показывается. LOOK/TALK сохраняют художественные ответы, остальные прежние
действия используют сценарный план в общем движке. Свободный план не создаёт произвольные
предметы, NPC, места, магию или новые бои; сценарный пошаговый бой реализован отдельно.
Постоянная память между перезапусками сервера не реализована. Смысловую уместность способа оценивает ИИ; сервер гарантирует
формальные ограничения сцены. Качество новых способов с реальной моделью требует отдельного прогона.

Команда сразу подтверждается; участники видят «Ведущий думает…». Владелец действия может отменить запрос;
во время общей паузы игровые команды заблокированы, подтверждённый выход доступен отдельно. Запрос не привязан к сокету:
после переподключения виден его текущий статус, повторной отправки в GPT Luna нет. Ошибка, отмена и таймаут
45 секунд сохраняют ход, ресурсы и журнал. Запоздалый ответ не применяется после отмены/перезапуска.
Черновик действия в открытом экране сохраняется для повторной отправки после ошибки.

Для контроля расхода: один запрос на отправленную реплику и ещё один после подтверждённого броска
(реакция либо эпилог). В текущем запросе передаётся `maxTokens=1200`, не более четырёх
параллельных запросов на экземпляр сервера, без автоматических повторов. При занятых слотах сервер
отклоняет новое действие до вызова API; попытку можно повторить вручную. В контекст входят состояние и
последние 16 записей журнала с ограничением длины. Долговременная память ещё не реализована.
Квота посредника может учитывать коэффициенты моделей; событие `ai_usage` содержит входные/выходные
токены по ответу API, а не остаток пакета AI STAR. Общий лимит расходов по ключу этот прототип не обеспечивает.
Ключи, реплики, промпты и ответы не включаются в диагностику. Не включайте DEBUG/TRACE-логирование Koog,
которое может содержать промпты. Ошибки провайдера показываются игрокам без исходных HTTP-тел.
Событие `ai_request_failed` содержит `reason`, `request_id`, `elapsed_ms`, а при HTTP-ошибке — `http_status`
и известный тип ошибки провайдера из разрешённого списка. Исходные сообщения исключений и HTTP-тела
не сохраняются. Ошибки разбора различают отсутствие JSON, обязательных полей, неизвестное действие и
неподходящую реплику. Usage сохраняется и для полученного, но отклонённого ответа.

В реальной пробе AI STAR ответ был получен, но не прошёл проверку игрового JSON. Поэтому формат явно
закреплён также в системной инструкции; корректный JSON в единственном Markdown-блоке допускается,
но весь объект всё равно проходит проверку полей и ограничений. На один нативный параметр schema не полагаемся.

Тесты используют подставного ведущего, MockEngine для реального клиента Koog и TCP с двумя KMP-клиентами;
платные запросы и секреты для них не нужны. 13.11.2026 проверен реальный вызов AI STAR с действием осмотра:
после уточнения формата получен валидный ответ, сервер применил действие и передал ход примерно за 5,2 секунды.
Это проверка подключения и одного действия, а не оценка качества полного приключения.

13.11.2026 также проверены три свободных действия с реальным Claude через AI STAR и двумя
WebSocket-клиентами в одной комнате: передача инструментов Рин → Мира (4,3 с), закрепление
верёвки Мирой (4,7 с), подъём Рин снаружи по закреплённой верёвке (5,3 с). Инструменты перенесены
без копирования, верёвка снята со снаряжения и закреплена в состоянии сцены. Для подъёма модель
предложила свободный план с проверкой ловкости сложности 8; серверный d20 = 20, модификатор +3,
герой перемещён в фонарную комнату, запас проверок уменьшен с 3 до 2. План до броска и итоговое
состояние совпали у обоих клиентов. Выполнены ровно три обращения к модели, без повторов.
Это подтверждение трёх способов и успешной ветки реального броска; неудачная ветка проверена
автоматическими тестами, качество всей импровизации этим прогоном не оценивалось.

## Game diagnostics

Logging uses [Kermit 2.2.0](https://github.com/touchlab/Kermit/releases/tag/2.2.0) with the `DndGame` tag. JSON encoding and parsing use [kotlinx.serialization](https://kotlinlang.org/docs/serialization-json-elements.html) 1.13.0. The compiler plugin generates serializers for game state and the network protocol; diagnostic JSONL continues to use buildJsonObject. The log schema remains timestamp/event/fields, with string-valued fields. Events are structured JSONL: session start, processed/rejected commands, rejection reasons, turn/round changes, checks and their dice/modifier/difficulty/result, hero health/location changes, and adventure endings. IDs connect commands to the originating player, session and turn. Raw player text, prompts and AI responses are excluded.

On the next Desktop launch, logs appear in `%LOCALAPPDATA%/dnd-game/logs/game.log` (or `user.home/dnd-game/logs` when LOCALAPPDATA is unavailable). Kermit's asynchronous rolling writer keeps `game.log` and `game-1.log`, approximately 5 MiB each. Override the directory with `DND_GAME_LOG_DIR` or the JVM property `dnd.game.logDir`. Logging is best-effort; output failures must not change a game action. The application also writes to its console.

```powershell
# Follow Desktop game events after launching the app
Get-Content -LiteralPath (Join-Path $env:LOCALAPPDATA 'dnd-game/logs/game.log') -Tail 100 -Wait

# Optional: choose the Desktop log directory before launching
$env:DND_GAME_LOG_DIR = Join-Path $env:TEMP 'dnd-game-logs'
.\gradlew.bat :desktopApp:run

# Android diagnostics with a connected device
adb logcat -s DndGame:I '*:S'
```

On iOS use Xcode/system logs; on Wasm use the browser console. No remote logging service is configured.

The user checks game design and UI. Agent verification uses tests, builds and programmatic log analysis; do not use computer-use or automate visual inspection of this game. The file-output integration test exercises the real Kermit writer without launching the UI and leaves sample JSONL under `game/build/test-logs`.
