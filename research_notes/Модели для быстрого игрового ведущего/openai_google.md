# OpenAI и Google для игрового ведущего

## Какие актуальные модели стоит проверить первыми

### Takeaway
На 15.11.2026 быстрый первый эшелон для сравнения — `gpt-6-luna` с `reasoning.effort:none` и `gemini-3.5-flash-lite` с минимальным мышлением. Для более сложных свободных планов и более требовательного текста кандидаты — `gpt-6.1-terra` с `none`/`low` и `gemini-3.8-flash` с `low`. Это рекомендации для локального сравнительного теста, не измеренный победитель.

### Cited Findings
- `gpt-6-luna` — актуальная наиболее эффективная OpenAI-модель для узких массовых задач: контекст 1,05 млн, Structured Outputs, функции и потоковый вывод. Режимы рассуждения: `none`, `low`, `medium` (по умолчанию), `high`, `xhigh`, `max`. Responses API поддерживает функции; Chat Completions — функции только при `reasoning_effort:none`. Стандартная цена за 1 млн токенов: $0,10 вход / $0,50 выход, кэшированный вход $0,01. Fast mode вдвое дороже; при входе свыше 272 тыс. есть надбавки. — [OpenAI: GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna).
- `gpt-6.1-terra` официально описана как быстрая эффективная модель для ясного естественного письма, визуального анализа и computer use. Поддерживает `none` и `low` (также более глубокие режимы), Structured Outputs и streaming, tool calling — через Responses API. Стандартная цена $1 вход / $5 выход за 1 млн токенов; кэшированный вход $0,05. — [OpenAI: GPT-6.1 Terra](https://developers.openai.com/api/docs/models/gpt-6.1-terra).
- `gpt-6.1-sol` — более дорогая модель сложной работы: $2 вход / $10 выход, минимальный reasoning `low` (режима `none` в перечне нет). Поддерживает Structured Outputs; вызовы инструментов требуют Responses API. Не первый выбор для каждого короткого игрового хода. Последнее предложение — вывод исследователя, а не benchmark. — [OpenAI: GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol).
- `gemini-3.5-flash-lite` имеет статус Stable и модельный ID без preview, предназначена для низкой задержки и больших объёмов. Контекст 1 048 576; выход 65 536; поддерживает структурированный вывод, функции, кэширование, но не Live API и не генерацию аудио. — [Google: модель](https://aistudio.google.com/docs/models/gemini-3.5-flash-lite), [Google: каталог](https://aistudio.google.com/docs/models).
- `gemini-3.8-flash` также Stable. Google позиционирует её как самый интеллектуальный Flash для сложных агентных задач. Поддерживает JSON-схемы, функции и контекст 1 048 576. Reasoning: `low`, `medium`, `high`; `minimal` не поддерживается и вызывает ошибку. — [Google: Gemini 3.8 Flash](https://aistudio.google.com/docs/models/gemini-3.8-flash).
- Gemini 2.5 Flash уже deprecated: для новых интеграций не выбирать; с 1 декабря 2026 запросы перенаправляются на 3.5 Flash-Lite. 2.5 Flash-Lite пока не deprecated, но доступ ограничивается существующими пользователями; Google рекомендует новые модели для новых проектов. — [Google: каталог](https://aistudio.google.com/docs/models).

### Inferences
- Первый честный A/B-тест: GPT-6 Luna/none против Gemini 3.5 Flash-Lite/minimal, одинаковый компактный контекст, JSON-контракт и 100–300 токенов видимого текста. Если нарушают смысловые правила — повысить режим или проверить Terra/Flash, а не сразу брать флагман на все запросы.
- Terra особенно интересна как один универсальный кандидат для русской литературной подачи плюс небольшого JSON-плана: её заявленная специализация включает естественное письмо, но именно русский отыгрыш ещё нужно проверить.
- Большой контекст не означает, что следует посылать всю историю: для нашей игры важнее короткая каноническая сводка и текущая сцена.

### Gaps
- Нет проведённых в этом проекте запросов к OpenAI или Google и нет достоверных p50/p95 на наших русских сценах. Ни скорость «менее секунды», ни превосходство в соблюдении наших механик утверждать нельзя.
- Официальные страницы не дают сравнительного теста русского NPC-отыгрыша именно на текущем контракте игры.
- Доступность этих моделей через пользовательский ключ AI STAR, цены посредника и маршрут до него не установлены. Официальная цена — цена прямого API, не AI STAR.

## Какие настройки влияют на задержку и стоимость

### Takeaway
У быстрого текста должен быть явно выбран низкий reasoning; дефолты не всегда самые быстрые. Измерять нужно полную задержку после клика и время первого токена отдельно. Оплата thinking-токенов важна даже при короткой видимой реплике.

### Cited Findings
- Google: у `gemini-3.5-flash-lite` по умолчанию `minimal`, доступны minimal/low/medium/high; у 3.8 Flash по умолчанию medium, минимальное значение low. `minimal` — близкий к выключенному режим с наименьшей задержкой, но не обещание отсутствия рассуждения. — [Google: Thinking](https://aistudio.google.com/docs/thinking#thinking-levels).
- Google Standard, USD за 1 млн токенов: 3.5 Flash-Lite $0,30 вход / $2,50 выход; 3.8 Flash $0,75 вход / $3,75 выход до 31.12.2026, затем $1,50/$7,50 с 01.01.2027. Выход включает thinking-токены. Free tier допускает использование данных для улучшения продуктов, paid tier — нет в указанной таблице. — [Google: Pricing](https://aistudio.google.com/docs/pricing#gemini-3.5-flash-lite), [Google: Flash pricing](https://aistudio.google.com/docs/pricing#gemini-3.8-flash).
- OpenAI советует измерять TTFT и end-to-end отдельно, смотреть p50/p95 на одинаковых типах задач; сокращать выход, число запросов и reasoning. Документация отдельно советует не применять LLM к детерминированной работе. — [OpenAI: Latency optimization](https://developers.openai.com/api/docs/guides/latency-optimization).

### Inferences
- Готовые механические действия, броски и известные последствия должны оставаться кодом. Короткий ответ без дополнительного запроса-маршрутизатора чаще выгоднее сложной цепочки «классификатор → планировщик → рассказчик».
- Если делить диалог и механику на модели, нельзя создавать два последовательных запроса на каждую обычную реплику: это способно потерять преимущество более быстрой модели.
- Цены выше подходят для сравнения прямых API при коротком контексте без внешних инструментов; коэффициенты посредника, сеть, очереди, ретраи и распознавание речи не включены.

### Gaps
- Реальное влияние Fast/Priority tiers на нашей географии и прокси не измерено. Платный ускоренный tier не доказывает выполнение нашего целевого p95.
- Пока нет оснований количественно обещать выигрыш от смены одной конкретной модели на другую.

## Насколько JSON гарантирует поддержание игровых правил

### Takeaway
Структурированный вывод помогает получить корректный контракт, но не делает модель источником игровых правил. Нужны прежние серверные проверки предметов, маршрутов, фактов, здоровья, очереди и результатов кубиков.

### Cited Findings
- OpenAI прямо ограничивает гарантию Structured Outputs завершёнными ответами без отказа: соблюдается поддерживаемая JSON-схема; приложение обрабатывает refusals, incomplete и API errors и проверяет бизнес-правила, не выраженные схемой. Для strict-режима корень — object, все поля required (необязательность через null), `additionalProperties:false`; вложенный anyOf поддерживается, но не корневой. — [OpenAI: Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
- Google поддерживает подмножество JSON Schema, рекомендует отдельно проверять значения и семантику. `minLength`/`maxLength`, уникальность элементов и ряд счётных ограничений не обеспечиваются грамматикой; minItems/maxItems обеспечиваются. Большие/глубокие схемы могут быть отклонены. — [Google: Structured outputs](https://aistudio.google.com/docs/structured-output#limitations).
- Google умеет stream структурированного ответа, но чанки являются частями JSON, которые надо собрать в итоговый объект. Нельзя считать первый чанк завершённым игровым решением. — [Google: Streaming structured outputs](https://aistudio.google.com/docs/structured-output#streaming).

### Inferences
- В нашем проекте строгий JSON и серверный валидатор — обязательный минимум для любого провайдера. Проверка JSON без SceneRules не предотвращает фиктивную победу, неверный расход предмета или неуместную характеристику.
- Отдельно оценивать: валидность схемы, долю принятых сервером планов, смысловое соответствие намерению, отсутствие знания скрытых фактов NPC, соблюдение speakerNpcId и отсутствие механик в речи.
- Нынешний проект использует Anthropic Messages через AI STAR. Замена провайдера требует нового серверного адаптера и тестов, а не простой подстановки чужого model ID. В этой задаче смена ключей/провайдера автоматически не авторизована и не выполнялась.

### Gaps
- Нет официальной гарантии точного исполнения нашей упрощённой системы у какой-либо из этих моделей. Победителя по качеству определит общий регрессионный набор игровых случаев, включая провалы и провокационные команды.
