# Anthropic и Mistral для игрового ведущего

Проверено по первичным источникам 15.11.2026. Внешних запросов к моделям в рамках этого исследования не выполнялось.

## Какие модели и цены подходят для коротких реплик и планов

### Takeaway
В семействе Claude основной кандидат на быстрый дешёвый игровой цикл — Haiku 5.5; Sonnet 5.5 полезнее оставить кандидатом для сложной импровизации. Mistral Small 4 — недорогой отдельный кандидат с явным режимом минимального рассуждения, но сравнительного игрового замера с ним нет.

### Cited Findings
- Claude Haiku 5.5: API ID `claude-haiku-5-5`, активная последняя модель, выпуск 07.10.2026. Контекст 1M, выход до 128K. Для запросов до 100K входных токенов цена $0.10 за 1M входных и $0.50 за 1M выходных; выше 100K — $0.50/$2.50. Производитель относит её к своему самому быстрому классу; adaptive thinking включён по умолчанию, default effort `medium`. Не переносить прямую цену Claude API на AI STAR. — [Официальная карточка](https://platform.claude.com/docs/en/models/haiku-5-5/overview)
- Claude Sonnet 5.5: API ID `claude-sonnet-5-5`, активная последняя модель, выпуск 28.09.2026; 1M контекст, 128K выход, $2/$10 за 1M входных/выходных токенов. Класс задержки производителя — Fast, adaptive thinking по умолчанию, default effort `high`. — [Официальная карточка](https://platform.claude.com/docs/en/models/sonnet-5-5/overview)
- Mistral Small 4: GA, версия 26.03, фиксируемый ID `mistral-small-2603`, контекст 256K, $0.15/$0.60 за 1M входных/выходных токенов. Карточка перечисляет Chat Completions, Function Calling и Structured Outputs. — [Официальная карточка](https://docs.mistral.ai/models/mistral-small-4-0-26-03)
- Mistral заявляет для Small 4 уменьшение полного времени ответа на 40% в своём latency-optimized setup, а также 3x throughput относительно Small 3. Это результат конфигурации производителя, не обещание миллисекунд для нашего сервера. — [Анонс Small 4](https://mistral.ai/news/mistral-small-4/)

### Inferences
- В сравнении прямых цен Haiku дешевле Sonnet примерно в 20 раз за одинаковое число токенов в коротком контексте. Это арифметика по тарифам, не стоимость игрового эпизода: токенизация, thinking, кэш и посредник меняют расход.
- У Mistral Small 4 технически достаточно контекста и типов API для текущего короткого сценария. Ни карточка, ни объявленная скорость не доказывают качество русской ролевой прозы или соблюдение наших сюжетных условий.

### Gaps
- Не найдено официального сравнительного теста русских NPC-диалогов и соблюдения именно наших правил для этих трёх моделей.
- Нет подтверждённой тарифной сетки AI STAR для этих моделей: только прямые тарифы производителей.

## Какие настройки дают скорость и структурированный ответ

### Takeaway
`effort=low` не означает, что thinking выключен. У каждой модели разные допустимые настройки; схема JSON проверяет форму результата, а разрешённость игрового действия всё равно должен проверять движок.

### Cited Findings
- Sonnet 5.5 принимает `thinking:{"type":"between_tools"}` при effort `high` или ниже — так выключается up-front thinking. `thinking:{"type":"disabled"}` для него возвращает 400. Haiku 5.5, наоборот, принимает `disabled` при effort `high` или ниже и не принимает `between_tools`. Без поля thinking обе модели используют adaptive thinking. — [Таблица режимов thinking](https://platform.claude.com/docs/en/build-with-claude/thinking)
- Effort задаётся как `output_config.effort`; `low` экономит токены/время, но может снижать возможности. Контроль действует на текст, вызовы инструментов и thinking. — [Effort](https://platform.claude.com/docs/en/build-with-claude/effort)
- Claude Structured Outputs использует `output_config.format` с `type:"json_schema"`; strict tool use — отдельный механизм проверки аргументов инструментов. У схем есть ограничения; SDK может убирать неподдерживаемые числовые/строковые ограничения из передаваемой схемы, оставляя проверку исходного контракта клиентскому коду. — [Structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)
- Для Small 4 `reasoning_effort="none"` даёт минимальное рассуждение и убирает thinking chunk; `"high"` включает полноценное рассуждение. Не использовать `"low"` как будто шкала универсальная для всех поставщиков. — [Mistral reasoning](https://docs.mistral.ai/inference/conversations/reasoning)
- Mistral предлагает обычный JSON mode и custom schema; рекомендует custom structured outputs как более надёжный вариант, сохраняя необходимость корректного промпта. — [Structured Outputs](https://docs.mistral.ai/inference/conversations/structured-output), [Custom schema](https://docs.mistral.ai/inference/conversations/structured-output/custom)
- Anthropic рекомендует для снижения задержки выбор быстрой модели, уменьшение входа/выхода, низкий effort и streaming; TTFT и полное время ответа — разные метрики. Streaming улучшает воспринимаемую отзывчивость, но не означает мгновенное завершение плана. — [Reducing latency](https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/reduce-latency)

### Inferences
- Изменение режима thinking — отдельный фактор для будущего контролируемого сравнения. Предыдущий сессионный тест только с effort `low` нельзя назвать тестом минимального рассуждения этих моделей.
- Нужны обе проверки: schema/type validation и правила ScenarioRules/AdventureEngine (ID, место, предметы, предусловия, допустимые последствия). Валидный JSON может предлагать неверный игровой эффект.
- Для субтитров и будущей озвучки можно стримить подтверждённую художественную речь, но механические последствия нельзя исполнять по неполному, ещё не проверенному JSON.

### Gaps
- Нельзя утверждать, что AI STAR пропускает все перечисленные параметры без изменения: требуется отдельная проверка через данный маршрут.
- Нет гарантированных TTFT/p95 прямого API в нашем регионе и при нашем размере промпта.

## Как интерпретировать текущие замеры и выбирать для игры

### Takeaway
Сессионные замеры не оправдывают автоматический переход всего проекта на Haiku. Они показывают, что нынешний маршрут AI STAR нужно оценивать как целую систему, включая параметры, промпт и тип действия.

### Cited Findings
- Официальный источник описывает Haiku как вариант для latency-sensitive нагрузок, но подчёркивает влияние сложности промпта и инфраструктуры на задержку. — [Reducing latency](https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/reduce-latency)
- Mistral Small 4 умеет сочетать обычный chat и сложное reasoning в одной модели с переключаемым effort. — [Анонс Small 4](https://mistral.ai/news/mistral-small-4/)

### Inferences
- Входные данные координатора из четырёх согласованных запросов через AI STAR (не новый внешний источник): Sonnet low NPC 4865 мс, свободный INT-план превысил 40010 мс; Haiku low NPC 9124 мс, INT-план 23823 мс. Все завершившиеся ответы прошли узкую проверку примера. На каждый тип всего один запрос, очередь/нагрузка неизвестны, запросы моделей выполнялись параллельно. Это не рейтинг прямых API и не p50/p95.
- Предлагаемый shortlist внутри этого подисследования: Haiku 5.5 с отключённым thinking как кандидат для короткой речи/простого структурированного намерения; Mistral Small 4 с `none` как дешёвый независимый кандидат; Sonnet 5.5 с `between_tools`/низким effort как запасной вариант более сложных действий. Это гипотеза для eval, не выбранная пользователем архитектура.
- Измерять на одинаковом корпусе: p50/p95 полного валидированного ответа, TTFT отдельно, долю принятых движком планов с первой попытки, смысловые ошибки, выход из роли NPC/рассказчика, реальный billed usage. Быструю неправильную реплику нельзя считать успешным быстрым ходом.
- Минимум 30–50 фиксированных игровых ситуаций полезнее ещё двух случайных вопросов: диалог, шутка с серьёзным действием, свободный способ с другой характеристикой, чужой ход, предмет не у героя, отмена, исчерпанный ресурс, закрытый маршрут, попытка присвоить победу.
- Для готовых механических кнопок LLM вообще не нужен: авторский сценарий и движок дадут наиболее короткий и предсказуемый путь; модель нужна для свободной речи и импровизации. Это вывод о текущем устройстве игры, не утверждение о скоростном превосходстве конкретного производителя.

### Gaps
- Ни одна из моделей не проверена здесь на большом корпусе русского ролевого текста; платных новых запросов этот исследователь не выполнял.
- Итоговый выбор между Anthropic/Mistral и моделями других исследователей должен учитывать результаты общих тестов и доступность реального API-аккаунта, без автоматической смены провайдера.
